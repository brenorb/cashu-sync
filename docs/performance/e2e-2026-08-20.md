# E2E performance — 2026-08-20

## Change

The local PWA server now gives hashed files under `assets/` an immutable one-year cache header while keeping the HTML document uncached. Reload-heavy wallet flows no longer redownload the large JS chunks within a browser context.

Repeated Playwright runs also have a no-build entry point:

```sh
cd wallet
npm run test:e2e:run
```

Use `npm run test:e2e` for a clean build plus run.

## Measured result

| Run | Result | Wall time |
| --- | --- | ---: |
| Previous `npm run test:e2e` | rebuilt PWA, then 4 skipped tests | 11.96 s |
| `npm run test:e2e:run` after the build | 1 cache regression test passed, 4 live tests skipped | 2.58 s |

The repeat loop was **78% faster** in this environment. The clean-build command is intentionally unchanged; its build time varies with the local Quasar/Vite cache and was not attributed to the server-cache change.

## Verification

- The cache regression test fails before the change (`assets/*.js` returned `no-store`).
- After the change: 1 targeted Playwright test passed.
- Full E2E command after the change: 1 passed, 4 skipped.
- The four wallet workflows were skipped because local Nutshell, sync relay, and pairing relay services were unavailable. Functional live-flow timing remains unmeasured until those services are running.
- ESLint passed.
