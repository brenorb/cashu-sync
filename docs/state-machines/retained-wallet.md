# Retained upstream wallet state machines

These are stateful paths in the checked-in Cashu.me base. They are listed so a file or transitive import does not get mistaken for a shipped Cashu Sync v0 feature. The [active route table](../../wallet/src/router/routes.js), [Quasar boot and PWA mode](../../wallet/quasar.config.js), [v0 feature profile](../../wallet/src/v0/profile/index.ts), and [UI surface tests](../../wallet/test/vitest/__tests__/v0-ui-surface.test.js) establish that boundary. The diagrams and verification skills model the active project-owned v0 behavior.

| Retained area | State machines | Source anchors / reachability |
|---|---|---|
| Upstream onboarding and restore | Welcome slide progression, setup/restore choice, seed/file/token input, seed-based mint scan, restore progress and completion. | [WelcomePage](../../wallet/src/pages/WelcomePage.vue), [welcome store](../../wallet/src/stores/welcome.ts), [Restore](../../wallet/src/pages/Restore.vue), [restore store](../../wallet/src/stores/restore.ts). No upstream welcome or restore route; active backup/restore is Recovery Settings. |
| Cashu tokens and locking | Send amount → proof selection or swap → reserve → display token → observe spend or unreserve; receive paste/scan → parse → choose/validate mint → redeem or retain on error; P2PK keys and lock/unlock. | [wallet store](../../wallet/src/stores/wallet.ts), [send store](../../wallet/src/stores/sendTokensStore.ts), [receive store](../../wallet/src/stores/receiveTokensStore.ts), [tokens](../../wallet/src/stores/tokens.ts), [P2PK](../../wallet/src/stores/p2pk.ts), [WalletPage](../../wallet/src/pages/WalletPage.vue). The active recovery escape hatch can export unaffected local tokens; that one path is inventoried under recovery. |
| Upstream Lightning and alternate rails | Invoice/offer/address input → decoded request → quote → pending, settlement or expiration → history; inbound/outbound worker queues and websocket subscriptions start, poll/receive, retry and stop; LNURL discovery followed by amount submission. | [wallet store](../../wallet/src/stores/wallet.ts), [Bolt11](../../wallet/src/stores/walletBolt11.ts), [melt](../../wallet/src/stores/walletMelt.ts), [Bolt12](../../wallet/src/stores/walletBolt12.ts), [on-chain](../../wallet/src/stores/walletOnchain.ts), [invoice worker](../../wallet/src/stores/invoicesWorker.ts), [workers](../../wallet/src/stores/workers.ts), [wallet websocket](../../wallet/src/stores/walletWebsocket.ts). The v0 route uses its separate journaled Bolt11 flow. |
| Mint selection, swaps and discovery | Select/add/switch mint and unit → refresh info/keys → activate or fail; cross-mint swap quotes → fund source/destination → settle or recover; discovery subscriptions/cache hydrate → enrich → persist/display; reviews, trust graph and price fetch refresh. | [mints](../../wallet/src/stores/mints.ts), [swap](../../wallet/src/stores/swap.ts), [mint recommendations](../../wallet/src/stores/mintRecommendations.ts), [Nostr user](../../wallet/src/stores/nostrUser.ts), [price](../../wallet/src/stores/price.ts). The active authority-mint bootstrap and proof projection use shared code; discovery, swapping between mints and mint selection are outside the v0 route. |
| Nostr identity and backups | Choose signer → initialize/retry/reset; DM subscriptions receive and parse token payloads; backup enable → derive key → publish or discover → select/import mints; NIP-60 wallet setup. | [Nostr](../../wallet/src/stores/nostr.ts), [Nostr mint backup](../../wallet/src/stores/nostrMintBackup.ts), [NIP-60](../../wallet/src/stores/nip60.ts). V0 pairing uses ephemeral gift wraps through its separate pairing module. |
| Payment connections and requests | NWC connect → subscribe → decode/dispatch command → reply → stop; npub.cash connect/auth → refresh or claim; NPC v2 update mint/username and ingest quotes; payment request decode → select delivery → submit or fail. | [NWC](../../wallet/src/stores/nwc.ts), [npub.cash](../../wallet/src/stores/npubcash.ts), [NPC v2](../../wallet/src/stores/npcv2.ts), [payment requests](../../wallet/src/stores/payment-request.ts). The v0 settings menu does not expose these paths. |
| Upstream browser/app packaging | Legacy layout/dialog UI state, global mutex, Capacitor back/clipboard, Android/iOS install prompts, extension host embed and custom Workbox navigation fallback. | [ui](../../wallet/src/stores/ui.ts), [boot](../../wallet/src/boot), [extension](../../wallet/extension), [custom worker](../../wallet/src-pwa/custom-service-worker.js). V0 reuses selected shared browser hooks; unused routes/boot entries and the custom worker are not alternate v0 lifecycle implementations. |

Tests, story CSVs, frozen documentation and binary artifacts are evidence or build products. They do not introduce separate product machines. Runtime behavior inside upstream dependencies, the external provider, and the Nutshell service is not checked-in project logic.
