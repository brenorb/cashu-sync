# Cashu Sync v0 state machine audit

The source baseline is [a9b401e](https://github.com/brenorb/cashu-sync/tree/a9b401ec6618c969b3d4e3aaeffac785d4aa0617), the fetched `origin/main`. Start with the [user flow diagrams](flows.md) or the [checker results and replays](results.md).

A machine here has a memory of prior events that changes what can happen next: a persisted journal, a relay head, an async session, a retry budget or a UI lifecycle. The table includes explicit phase names where the transitions across stores, callbacks and services are still implicit. An arrow ending in an error can leave durable data intact. This inventory follows the active routes and build hooks through the browser, both Go services, and the project-owned release and mint fixture code. It treats library internals, the external mint and provider as interfaces. It excludes trivial display toggles unless they affect what a person can do or what status they see.

## Retained code and coverage boundaries

See the [retained upstream wallet inventory](retained-wallet.md) for inactive and feature-gated machines, including their state transitions and implementation anchors.

- The shipped route table uses `V0WalletPage.vue`, sync/recovery, appearance/language/about, the already-running screen and fallback. The active Quasar boot list is `base`, `global-components`, and `i18n`; production PWA uses generated Workbox, so the checked-in custom worker is not the active worker. Static assets, translations, fixture JSON, benchmarks and QA logs do not add runtime machines.
- The vendored wallet retains the upstream welcome slides and restore wizard; old wallet page, amount/send/receive and payment dialogs; mint discovery, review and ratings; invoice/token check workers and wallet subscriptions; Nostr login, backups, NIP-60, npubcash, payment requests and NWC; P2PK/send/receive, swap, Bolt12/on-chain/LNURL and upstream settings. These are legacy machines or disabled entry points, not alternate v0 flows. Shared stores still supply mint bootstrap, seed, migrations, payment history, proofs, preferences and camera to v0, and those active paths are accounted for above. The extension embedder and unselected boot modules are retained packaging, not alternate shipped V0 entry points.
- The audit compares the fetched default branch; the fetched recovery-checks and watch-quota branches are separate revisions. It does not assert behavior of a deployed instance, Docker runtime, third-party service, or the internals of Cashu SDK, Khatru, SQLite, IndexedDB, Vue or Workbox. Checkout tests and finite models cover selected observable interactions with these boundaries.
