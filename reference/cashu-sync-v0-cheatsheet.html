Lesson 1 · quick reference

Cashu Sync v0

One user, multiple fully authorized PWAs, one encrypted revision chain. Nutshell decides money; the relay decides which encrypted snapshot is current.

Three authorities

ComponentIt is authoritative forIt must never become
Wallet + IndexedDBPlaintext secrets, exact prepared requests, local crash journal, snapshot validation.The sole backup or monetary truth.
Nutshell mintQuotes and proof state: whether value was issued, pending, spent, or paid.The synchronized device state.
Silent Link relayCurrent encrypted event head and CAS acceptance.A balance calculator, decryptor, or mint participant.

Normal mint/melt order

1 · LocalPrepare exact request and persist one pending operation.
2 · RelayPublish encrypted child with prev = head; CAS must accept.
3 · MintSubmit the exact request to Nutshell; never regenerate outputs.
4 · FinalizePersist response/change, then publish a snapshot clearing the journal.

A timeout after submission is not a failed operation. Keep the journal and reconcile using quote state, NUT-19 replay when available, and exact NUT-09 restoration for mint outputs.

Privacy ledger

ProtectedStill visible or possible
Relay cannot read proofs, seed, balance, quotes, history, or operation details.Relay sees stable sync pubkey, timestamps, ciphertext size, IP/access timing, and a linkable event chain.
Invalid signatures, wrong keys, tampering, rollback, and broken predecessor links fail before local apply.Relay can withhold/delete/rollback storage and therefore hurt availability and recovery.
Pairing request has no wallet secret; formal response is NIP-44 encrypted to an ephemeral key.Live UI quick-pair is a time-limited bearer URL: ciphertext and its temporary passphrase travel together.
Paired devices do not exchange ecash; they converge on one encrypted snapshot.Every paired device has the mnemonic and can spend everything; v0 has no revocation.

Best next improvements

  1. Move quick-pair authority out of URL query material; wire the ephemeral two-QR flow or use an out-of-band authenticated channel.
  2. Replace plaintext mnemonic storage in browser localStorage and coordinate service-worker updates around in-progress operations.
  3. Add a threat-model review and independent audit for browser storage, pairing, relay metadata, and deployment.
  4. Only then consider per-device keys/revocation, multiple relays, or an event-sourced multiwriter model.
